Grok Build es el agente de código de xAI para la terminal. Su documentación de referencia es corta: "ejecutar `grok` sin argumentos arranca la TUI interactiva", los subcomandos cubren inicio de sesión, configuración y modelos, y el uso se mide por producto en tu cuenta de xAI. El dial muestra la ventana de créditos de Grok Build tal como la publica xAI.

## Instalar en Windows

xAI sirve un instalador de PowerShell:

```powershell
irm https://x.ai/cli/install.ps1 | iex
```

## Instalar en macOS

Y un instalador de shell para macOS y Linux:

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
```

## Iniciar sesión

```bash
grok login
```

Se abre el navegador para tu cuenta de xAI. En una máquina sin navegador, `grok login --device-auth` usa el inicio de sesión por código de dispositivo; `grok logout` borra las credenciales guardadas.

## Qué lee Tokendial

La CLI guarda sus credenciales en un archivo, igual en los dos sistemas:

- Windows y macOS: `~/.grok/auth.json`

El archivo tiene una entrada por CLI que inició sesión, identificada por emisor y cliente. Tokendial solo se fía de las entradas emitidas por `https://auth.x.ai`; lo que apunte a otro emisor es un despliegue a medida y se deja en paz. El token se lee en solo lectura y nunca se refresca, escribe ni copia, y con él Tokendial pregunta a xAI el uso actual del producto Grok Build.

## O deja que Tokendial lo haga

<Figure src={rows} alt="Tres filas de proveedor en los ajustes de Tokendial, cada una con un botón Instalar y los pasos Instalar, Iniciar sesión, Listo" caption="Una fila de proveedor mientras falta su CLI." ours="una captura de Tokendial 0.1.0 en Windows" locale="es" />

En los ajustes de Tokendial la fila de Grok muestra **Instalar → Iniciar sesión → Listo** mientras falte la CLI. Pulsa **Instalar**, revisa el comando, pulsa **Ejecutar**: el instalador corre en una terminal visible, `grok login` sigue en la misma ventana y el dial se conecta cuando llega la credencial. Nada se ejecuta hasta que pulsas el botón.
