Grok Build is xAI's coding agent for the terminal. Its reference documentation is short: "running `grok` with no arguments starts the interactive TUI", subcommands cover sign-in, configuration and models, and usage is metered per product on your xAI account. The dial shows the Grok Build credits window as xAI publishes it.

## Install on Windows

xAI serves a PowerShell installer:

```powershell
irm https://x.ai/cli/install.ps1 | iex
```

## Install on macOS

And a shell installer for macOS and Linux:

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
```

## Sign in

```bash
grok login
```

The browser opens for your xAI account. On a machine without a browser, `grok login --device-auth` uses device-code sign-in; `grok logout` clears the cached credentials.

## What Tokendial reads

The CLI stores its credentials in one file on both systems:

- Windows and macOS: `~/.grok/auth.json`

The file holds one entry per signed-in CLI, keyed by issuer and client. Tokendial trusts only entries issued by `https://auth.x.ai`; anything pointing at another issuer is a custom deployment and is left alone. The token is read read-only and never refreshed, written or copied, and with it Tokendial asks xAI for the current usage of the Grok Build product.

## Or let Tokendial do it

<Figure src={rows} alt="Three provider rows in Tokendial's settings, each with an Install button and the steps Install, Sign in, Ready" caption="A provider row while its CLI is missing. Interface shown in Spanish." ours="a screenshot of Tokendial 0.1.0 on Windows" locale="en" />

In Tokendial's settings the Grok row shows **Install → Sign in → Ready** while the CLI is missing. Press **Install**, review the command, press **Run**: the installer runs in a visible terminal, `grok login` follows in the same window, and the dial connects when the credential lands. Nothing runs until you press the button.
